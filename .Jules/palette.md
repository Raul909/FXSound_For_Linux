## 2024-03-06 - Improve accessibility for icon-only buttons and labeled selects
**Learning:** In React implementations where generic `<div>`s are used as visual labels next to interactive elements, screen readers will completely fail to associate them unless explicitly linked using `id` and `aria-labelledby`. Also, icon-only buttons that convey binary state (like power) must combine `aria-label` with `aria-pressed` to correctly indicate both function and current status to assistive technologies.
**Action:** When adding or reviewing custom interactive components (like dropdowns and status toggles), verify that visual text is explicitly linked to `<select>` or `<input>` tags using proper ARIA attributes, and ensure all purely visual icon buttons have corresponding textual alternatives and explicit state announcements.

## 2024-03-24 - Provide keyboard navigation for custom generic visual UI components
**Learning:** In React implementations where generic `<div>`s are used to represent custom UI elements like sliders or complex controls, screen readers and keyboard users cannot interact with them unless explicit keyboard interaction (e.g., handling Arrow keys, Home, End, space, enter) and ARIA attributes (e.g., `role="slider"`, `tabIndex`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-label`) are added.
**Action:** Always ensure that custom generic UI components built with tags like `<div>` have a `role`, appropriate ARIA state attributes, `tabIndex`, and `onKeyDown` listeners to ensure functional keyboard parity with native elements. Also, ensure elements like sliders support common keyboard modifiers such as `Shift` + arrow key for large stepping, and include `:focus-visible` styling for visual clarity.
