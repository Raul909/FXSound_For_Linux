## 2024-03-06 - Improve accessibility for icon-only buttons and labeled selects
**Learning:** In React implementations where generic `<div>`s are used as visual labels next to interactive elements, screen readers will completely fail to associate them unless explicitly linked using `id` and `aria-labelledby`. Also, icon-only buttons that convey binary state (like power) must combine `aria-label` with `aria-pressed` to correctly indicate both function and current status to assistive technologies.
**Action:** When adding or reviewing custom interactive components (like dropdowns and status toggles), verify that visual text is explicitly linked to `<select>` or `<input>` tags using proper ARIA attributes, and ensure all purely visual icon buttons have corresponding textual alternatives and explicit state announcements.

## 2024-04-07 - Implement fully accessible custom slider components
**Learning:** When building custom interactive range inputs (like EQ bands and effect sliders) using generic `<div>` elements, standard visual interactions (mouse/touch) are not enough for screen readers and keyboard users. Custom components must explicitly implement W3C ARIA roles (`role="slider"`), range attributes (`aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-orientation`), focus management (`tabIndex`), linking to visual labels (`aria-labelledby` or descriptive `aria-label`), explicit keyboard handlers (`Home`, `End`, `Arrow` keys), and clear visual focus indicators (`:focus-visible`).
**Action:** When implementing custom interactive inputs, always provide complete semantic ARIA mappings, W3C-compliant keyboard interaction handlers, and explicit focus styling to guarantee parity with native form elements.
