## 2026-05-03 - Mitigate Mutex Poisoning DoS
**Vulnerability:** Mutexes used to guard shared application state (`AppState.audio_engine`) and audio processor data structures in Rust were unwrapping or mapping errors to strings on poisoned Mutexes. When a thread panics while holding the Mutex, the Mutex becomes poisoned, and subsequent accesses would either panic or return errors, leading to a permanent Denial of Service (DoS) for the application or audio subsystem.
**Learning:** Returning errors or unwrapping poisoned Mutexes fails to clear the poison state and propagates the failure. In state that can tolerate the panic (e.g., shared audio processing state without strict invariant breakage on panic), the Mutex guard should be recovered to maintain uptime.
**Prevention:** Use `.unwrap_or_else(|e| e.into_inner())` instead of `.unwrap()` or `.map_err(...)` to safely recover the MutexGuard and clear the poison state, ensuring application resilience against unexpected panics in other threads.
