## 2024-05-18 - [Tauri CSP Misconfiguration]
**Vulnerability:** The Tauri configuration (`src-tauri/tauri.conf.json`) had `app.security.csp` set to `null`, completely disabling Content Security Policy protections.
**Learning:** Setting CSP to null in Tauri exposes the application to Cross-Site Scripting (XSS) risks by allowing execution of unauthorized scripts and loading of resources from any origin.
**Prevention:** Always define a strict baseline CSP, such as `"default-src 'self'; style-src 'self' 'unsafe-inline'"`, in Tauri applications to restrict script execution and resource loading to trusted sources.
## 2024-05-24 - [CRITICAL] Fix DoS vulnerability via cascading panics on Mutex locks
**Vulnerability:** Calling `.unwrap()` on `Mutex` locks in real-time audio processing threads (`src-tauri/src/audio.rs`) introduces a Denial of Service (DoS) vulnerability. If a thread panics while holding the lock, the Mutex becomes "poisoned." Subsequent attempts to lock the Mutex by other threads will result in a `PoisonError`, and calling `.unwrap()` on this error will cause those threads to panic as well, leading to a cascading failure and complete application crash.
**Learning:** In highly concurrent, real-time applications, especially those interacting with hardware or native libraries (like PulseAudio), panics can occur unexpectedly. Hardcrashing the entire application on a transient thread failure reduces availability and resilience.
**Prevention:** Avoid calling `.unwrap()` on `Mutex` locks. Instead, handle potential `PoisonError`s safely by using `.unwrap_or_else(|poisoned| poisoned.into_inner())` to recover the `MutexGuard` and allow the application to continue functioning, albeit potentially in a degraded but safe state.
